# Final Integrated Review (independent reviewer)

Independent final reviewer, 12 October 2026. I was not involved in producing this design and did not read the authors' self-assessment before forming my own verdicts. I checked the governing prompt's pre-handoff checklist item by item against the twenty-five files under `design_audit/`, and I re-verified twelve reference-repository claims directly in the read-only clones. This file is the only file I wrote; I changed nothing else.

## Summary verdict: **ready with fixes**

The design is substantially stronger than the concept it audits, and it is honest where honesty is costly. Three things in particular hold up under adversarial reading. First, the acceptance target has a real home: the per-candidate, per-criterion Assessment record plus a structured Reason record with enumerated disqualifiers (`optimized_design.md` §4.11) is the mechanism that makes "every compound, every criterion, a reason" checkable rather than rhetorical. Second, the hardest methodological trap in the assignment — that recovering the authors' eleven CQAs is unfalsifiable if the deriving agents can read them, yet unreachable if derivation must be blind to a disclosed reference outcome — is confronted explicitly and resolved with mechanical records rather than a norm (§8.6, ADR-13). Third, the no-backend route is described as coverage-limited rather than quality-limited, with a per-dimension `tool_coverage` disclosure on every snapshot, so a lookup over a well-studied subset cannot later be narrated as a screen of 3,171 compounds (§16; `case_study_protocol.md` §3.3).

No implementation code exists anywhere, and no ranking, threshold, or sensitivity outcome is reported as a result. The defects I found are localized: six unresolved placeholder markers in one specification, a miscount in the rebuttal mapping, a paraphrase labelled verbatim, one genuine layer-boundary wrinkle, and a set of wireframe numbers that lack the placeholder disclaimer their siblings carry. Eleven of fifteen items pass; four are partial; none fails. All four partials are repairable by edits to text that already exists, without new design work, so this is a handoff-ready package conditional on those fixes.

## Detailed findings

### F1. `rebuttal_alignment.md` miscounts its own claims, and the paragraph-3 range is wrong

- **Issue.** §2 states "The three draft paragraphs are split into eighteen material claims. Paragraph 1 is C1.1–C1.7, paragraph 2 is C2.1–C2.6, paragraph 3 is C3.1–C3.5." The document actually contains nineteen claims, and paragraph 3 runs C3.1 to **C3.6**. C3.6 ("the final 11 CQA criteria … candidate-level decisions and computational outputs") is one of the three claims marked unestablished as worded, so the omitted id is not a trivial one. `collaboration_log.md` §7.1 repeats the error ("eighteen claims").
- **Location.** `rebuttal_alignment.md` §2 preamble; claim block at §2 "C3.6"; `collaboration_log.md` §7.1 Fork C row.
- **Importance.** Medium. This document's function is a completeness guarantee for the rebuttal; a reader who checks the stated range against the content finds the accounting wrong, which undermines the one claim the document most needs to make about itself.
- **Required change.** Replace "eighteen" with "nineteen" and "C3.1–C3.5" with "C3.1–C3.6" in `rebuttal_alignment.md` §2, and correct the Fork C row in `collaboration_log.md` §7.1.

### F2. The case protocol labels a composite paraphrase as the verbatim objective

- **Issue.** `case_study_protocol.md` §2.1 sets `objective_text` to "the manuscript's stated objective, verbatim: a single orally administered agent that concurrently engages the stated tumour-microenvironment targets, with a pharmacological profile suitable for clinical development". The manuscript extract contains the component phrases in dispersed form ("To discover a single agent capable of simultaneously inhibiting the core TME drivers"; "pharmacological profile for oral administration") but not this sentence. The field is therefore a reconstruction presented as a quotation, in a design whose own rule is that `objective_text` is "verbatim; never rewritten by the system" (`optimized_design.md` §2.2, §4.4).
- **Location.** `case_study_protocol.md` §2.1, `objective_text` row; compare `optimized_design.md` §2.2 and §4.4; manuscript text extract lines 99 and 132 (scratchpad PDF extract).
- **Importance.** Medium. Every derived criterion is downstream of the objective text. A composite objective asserted as verbatim is precisely the class of unlabelled reconstruction the governing prompt warns against, and it would propagate into the preregistered policy stage.
- **Required change.** Either quote the manuscript sentence(s) exactly with their location, or set the row to a reconstruction marked `provenance_form: reconstructed_pending_author_confirmation` and add it to §2.3 input dependencies as an author-confirmation item.

### F3. The core owns a domain-shaped capability vocabulary

- **Issue.** `optimized_design.md` §7.1 fixes `capability` to a "core list": `identity_resolution`, `interaction_evidence_lookup`, `interaction_estimate`, `property_estimate`, `literature_retrieval`, `document_reading`, `dataset_context_lookup`, `rule_evaluation`. Three of these are pharmacology-shaped. §0.1 states that Core "must never own … domain vocabulary", and §2.1 assigns vocabularies to the adapter. `tools.md` §1 and `module.md` propagate the core-list framing. A second adapter would inherit drug-derived capability names, which is the drift the three-layer rule exists to prevent.
- **Location.** `optimized_design.md` §7.1 versus §0.1 and §2.1; `tools.md` §1 conventions; `module.md` §1.
- **Importance.** Medium. It does not block the primary case, but it is the one place where the separation the whole package advertises is not actually held, and it is cheap to fix now and expensive to fix after implementation.
- **Required change.** Either (a) rename the core capabilities to domain-neutral kinds (`entity_resolution`, `relationship_evidence_lookup`, `relationship_estimate`, `attribute_estimate`, `source_retrieval`, `document_reading`, `dataset_context_lookup`, `rule_evaluation`) and let the adapter bind drug meanings in its Vocabulary port, or (b) state explicitly in §0.1 and §7.1 that the capability vocabulary is an adapter-declared registry whose v1 instance is drug-shaped, and record the choice as an ADR. Option (a) is preferable; option (b) is acceptable if the deviation is declared rather than silent.

### F8. Two genuinely load-bearing defaults are stated once and not surfaced where they bind

- **Issue.** Two decisions that a later implementer will treat as adjustable are in fact structural. (a) `optimized_design.md` §8.3 records that criterion derivation runs `reference_disclosed` and that "full blindness is not claimed", with the reference-blind evidence slice as a partial measure; this is the honest choice, but the consequence — that no acceptance claim in this design rests on a blind derivation — appears in §8.3, §4.2 of the protocol and ADR-13 without ever being stated in the one-paragraph acceptance framing at §1. - **Location.** `optimized_design.md` §1 versus §8.3 and ADR-13; `optimized_design.md` §4.11 and §8.4, `leaderboard_spec.md` §3.3, `case_study_protocol.md` §10 items 8 and 12.

## Five most consequential residual risks for implementation

1. **Author-supplied inputs gate both acceptance targets.** The 3,171-compound identity list and the authors' eleven CQAs with a completeness attestation are absent from the package (`case_study_protocol.md` §2.3; `resources.md` §2.1; U-07). Without the first the case cannot run at the stated scale; without the second Target A cannot be scored at all, and "most of the original criteria" has no denominator. The design records these correctly as dependencies, but no amount of architecture removes them, and a `partial` attestation silently changes what the recovery fraction means.
2. **Expert throughput is the real rate limiter.** The trigger table requires an `hd_` record before every hard exclusion enters `confirmed` and before any `recommended` publication (§12.1), and `case_study_protocol.md` §10 lists twelve classes of expert decision. Each is correct; together they mean the primary case's wall-clock is set by expert availability, and the C1.6 rebuttal claim fails outright without recorded decisions. No batching or sampling discipline is specified to make this affordable.
3. **The coverage-limited no-backend route will probably produce a small or empty recommended set.** The design says so plainly and treats it as a correct outcome (§16; `case_study_protocol.md` §3.3). The risk is organizational rather than technical: an empty or single-entry shortlist with 2,900-odd unassessed candidates is a weaker-looking result than the manuscript's, and the pressure to relax the coverage floor or admit predicted values for hard rules will arrive precisely when the floor sits inside the admission-predicate hash and so cannot be moved without an expert decision. That guard is the right one; it will be tested.
4. **Evaluator exploitation and underpowered promotion.** The literature basis is unusually strong here (hidden detectors, 73.8% proxy-only gains, +0.0 held-out at matched budget) and the promotion conjunction is correspondingly strict (§13.7). The consequence is that for a long period nothing will be promotable, and U-02 concedes that affordable repeat counts and variance are unknown; `evaluation_plan.md` §12 already admits E3/E5 may be underpowered and reportable only descriptively. Implementations under schedule pressure tend to weaken exactly this gate.
5. **Record volume and projection determinism.** One assessment and one reason record per candidate per criterion across a 3,171-compound universe, plus an append-only journal that is the sole source of truth and whose projections must be bit-identical across replays (T0.5), is a real engineering load with no sizing estimate anywhere. ADR-01 names write amplification as the tradeoff; §14 defers to "local-first single-node file or embedded-database class"; U-08 leaves durability open. This is the most likely place for an implementation to quietly break the guarantee that every number is a fold over events.

## Places where a document overstates what the design can guarantee

- **`optimized_design.md` §4.12, "cross-context aggregation is impossible by construction".** A mandatory `task_context_id` on every row makes aggregation *detectable and illegitimate*, not impossible; nothing physically prevents a consumer from grouping rows. The invariant list in `leaderboard_spec.md` §13 item 4 states the enforceable version ("no view sums entries across task contexts"). Prefer that wording.
- **`optimized_design.md` §7.7, "How a successful call never validates a claim".** The five mechanisms are good, but four are write-path constraints and one is a rendering rule; they prevent a *tool* from writing a verification status, not a human or an agent from narrating a prediction as a measurement in prose outside the record set. The §7.7 heading claims more than the mechanisms deliver; "cannot be recorded as validation" is the accurate claim.
- **`iteration_and_provenance_spec.md` §2.5**, which says the reference application's counter-reset defect "cannot occur because `seq` is journal-assigned and never resets within a run". That holds for `seq`; the user-visible denominator can still change mid-stage, which is why `progress.estimate_revised` exists. The sentence should be scoped to sequence numbering.
- **`audit_report.md` §8**, the pre-handoff self-assessment, answers "yes" to all thirteen rows including "No implementation code … (checked by grep)" and architecture sufficiency. The code answer is correct and I verified it independently; but a self-assessment that returns thirteen unqualified yeses, written by the same agent that wrote the documents being assessed, reads as weaker evidence than the underlying work deserves. Recommend marking the rows this review downgrades and pointing to this file, which §8's closing line already anticipates.
