# Workstream 6a — Literature Investigation A: Agent Systems, Orchestration, Memory, Tool Use, Evaluation, and Agentic Scientific Discovery

Prepared by Workstream 6a (Literature Investigator A), a Claude Code subagent (model Fable 5.1, `claude-fable-5-1`) spawned by the coordinating agent. Date of execution and **search cutoff: 12 October 2026 (UTC)**. Window prioritized: October 2025 – October 2026, plus foundational work. Scope boundary: RSI / self-evolving agents and the negative evidence on debate and extra rounds belong to Workstream 6b; two bridging sources are cited here (Self-Harness; the HAL reasoning-effort finding) and not analysed in depth. Design only; no implementation code.

## 1. Summary

1. The most consistent evidence in the window concerns the orchestrator and verification, not the executors. MAST (NeurIPS 2025 Datasets & Benchmarks) attributes 43.7% of multi-agent failures to system-design/specification issues and 24.45% to weak verification; a May 2026 attribution study finds the orchestrator responsible for a mean 67.7% of failures in orchestrator–executor topologies. Components 2 (Planner/Delegator) and 3 (Proposer–Critic) are where this design carries the most risk.
2. Evaluation methodology has matured faster than methods. ABC, HAL and AstaBench (ICLR 2026) converge on cost-controlled, tool-standardized, log-inspected evaluation with trivial-agent baselines and date-cut corpora; AstaBench shows per-step success near 70% collapsing to roughly 3% for completing all steps of an end-to-end research task. Component 13 should adopt these as requirements.
3. Memory and skill evidence is positive but conditional. Itemized, delta-updated memory (ACE, ICLR 2026) beats full-rewrite memory and GEPA on agent tasks, but loses 3.4 points when feedback lacks ground truth; skill-retrieval precision falls from 29.6% to 3.3% as the pool grows from 5 to 100; cross-role skill transfer can cost 4.8–7.5 points. Component 9 must be small, scoped, provenance-tagged and promotion-gated.
4. Citation verification is verifier-dependent (3–18% unsupported-citation rate on identical outputs), and Kosmos's interpretive statements were only 57.9% accurate against 85.5% for data-derived statements. The Evidence Ledger (5) must record claim type and verifier identity, not just support/conflict.
5. Reflective prompt optimization (GEPA, ICLR 2026 Oral) is credible as an offline, metric-driven strategy-evolution engine (35× fewer rollouts than GRPO) but requires a scalar metric plus textual feedback and spends most of its budget on validation; it belongs in component 13, not inside a run.

**Three design changes most recommended.**
- **A (components 2, 3, 4).** Make the delegation brief a typed artifact with mandatory objective, output contract, allowed tools/sources, boundaries, budget and completion check; return subagent results to the planner as structured summaries with ledger references, never raw transcripts.
- **B (component 13).** Specify the Evaluation Harness now as: fixed evidence snapshot with date cutoff; identical tool set for every compared policy; trivial-agent, single-pass and fixed-round baselines; pass^k reliability over repeated seeds; time-invariant cost accounting; mandatory transcript inspection against a scanner checklist; held-out criteria.
- **C (component 9).** Redefine Scoped Memory as itemized entries with helpful/harmful counters, provenance, scope tags and a held-out promotion gate; cap the active pool per scope; forbid whole-memory rewrites; label self-judged outcomes as such.

## 4. Findings

### F1. Delegation is the failure locus; the delegation brief and result return must be typed artifacts
- **Issue.** The spine describes the Planner/Delegator as "decomposes into steps with owners, budgets, and completion criteria" but does not say what a delegation carries or what comes back. The evidence says this is where multi-agent systems fail: S1 attributes 43.7% of failures to specification/design (disobeying task specification 11.8%, step repetition 15.7%, unawareness of termination conditions 12.4%); S2 attributes a mean 67.7% of failures to the orchestrator "gradually losing control of the task", with loops, premature termination, and inability to "synthesize conflicting reports"; S3 reports that 80% of its performance variance is explained by token usage and that subagents fail without "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries".
- **Source / location.** S1 arxiv.org/html/2503.13657v3 (Sections 4, Appendix G; accessed 2026-10-12); S2 arxiv.org/html/2606.01351v1; S3 anthropic.com/engineering/multi-agent-research-system.
- **Importance.** High: in this case the planner must coordinate evidence retrieval, criterion proposal, per-candidate assessment and leaderboard updates across 140 candidates; an orchestrator that loses state will produce exactly the untraceable rationale the rebuttal cannot afford.
- **Recommended change (components 2, 3, 4).** Define a *Delegation Brief* record: `brief_id`, `parent_step_id`, `objective` (one sentence), `output_contract` (artifact type and required fields), `allowed_tools_and_sources`, `scope_boundaries` (what not to do), `budget` (tool calls, LLM turns, wall time), `completion_check` (how the planner verifies done), `evidence_cutoff_ref`. Define a *Result Return* record: `brief_id`, `status` (completed / rejected / unresolved), `structured_summary` (bounded length), `ledger_refs`, `artifact_refs` with versions, `budget_consumed`, `open_issues`. Policy: the planner's context receives only Result Returns and ledger references; raw transcripts go to the Event Journal (11). Add S3's effort-scaling rule as a declarative table in the case configuration (simple lookup: one worker, few calls; comparison: several workers; full derivation: many).
- **Tradeoff.** Structured summaries can drop nuance; provide an explicit "request detail" path that returns a bounded excerpt by event sequence number rather than the whole transcript. Roughly 15× token cost of chat (S3) must be budgeted.
- **Unresolved uncertainty.** S2 does not report trace counts or inter-annotator agreement; S3 is a vendor post with an unpublished internal evaluation.

### F2. Verification must be multi-level and typed; a critique without an objective-level check adds little
- **Issue.** The Proposer–Critic protocol lists typed artifacts but does not specify what a critique must check. S1 finds 24.45% of failures in task verification (no/incomplete 8.2%, incorrect 9.1%, premature termination 6.2%) and states "sole reliance on final-stage, low-level checks is inadequate"; adding an objective-level verification step to ChatDev gave +15.6% while prompt-level "tactical" fixes were "not consistent". S23 finds agents using explicit verification 13–87% more likely to succeed and mid-run self-correction raising success 1.5–4×. S30 (citing a secondary study) reports that evidence was ignored in 68% of traces and refutation-driven belief revision occurred in 26%.
- **Source / location.** S1 (FC3 insight; Appendix G.2); S23 arxiv.org/html/2510.11977v1 (log-inspection section); S30 arxiv.org/html/2605.08956v2 (Section on alternative views).
- **Importance.** High: the brief already warns that role separation "does not itself establish independent verification"; the evidence confirms that unspecified critique is one of the two dominant failure classes.
- **Recommended change (component 3).** Make the *Critique* artifact a list of typed checks: `check_id`, `target_artifact_version`, `check_type` ∈ {objective conformance, evidence support (ledger refs present and status supported), unit/applicability consistency, counter-evidence considered, candidate-symmetric scrutiny (same test applied to surufatinib and competitors), termination condition met}, `verdict` ∈ {pass, fail, unknown}, `severity`, `evidence_refs`, `actionable_next_step` (evidence request / tool request / human review). A proposal cannot move to `completed` unless the objective-conformance and counter-evidence checks have verdicts. Keep the arbiter as a separate record kind, invoked only on persistent disagreement, as the spine already states.
- **Tradeoff.** More tokens per review exchange; S1 cautions that inter-agent misalignment failures (31.85%) are not fixed by protocol alone.
- **Unresolved uncertainty.** The 68%/26% figures come from a study quoted in S30 (Ríos-García et al., 2026) that I could not access; treat them as indicative.

### F3. Tool contracts should carry side-effect class, idempotency and structured diagnostics; schemas reduce interface errors but not semantic ones
- **Issue.** The Tool Broker promises "declarative tool contracts" and "structured results and errors". S16 (a one-model pilot) shows JSON Schema contracts cut invalid calls from 5.39 to 3.72 and execution failures from 0.54 to 0, but semantic misuse rose (0.93→3.03) and task success stayed at 0.0, so schemas alone do not buy correctness. S17 reports that idempotency keys reduce duplicate side effects from 28% to 4%, that under in-flight or duplicated transport frontier models duplicate in 56–74% of cases, and that agents "reported success in 90% of episodes despite duplicating effects". S23 observes that on SciCode and CORE-Bench agents "almost never completed a run without a single tool calling failure". S18 reports recovery dropping about 37% under implicit semantic tool failures.
- **Source / location.** S16 arxiv.org/html/2603.13404; S17 arxiv.org/abs/2609.29095; S18 arxiv.org/abs/2606.05806; S23 as above.
- **Importance.** Medium-high: the case will call evidence-source adapters, a rule engine, and an optional CDES adapter; a successful call must never be mistaken for a validated claim (brief §4), and duplicate writes to the ledger or leaderboard would corrupt provenance.
- **Recommended change (component 4).** *Tool Contract* fields: `tool_id`, `version`, `input_schema`, `output_schema`, `side_effect_class` ∈ {read, idempotent write, non-idempotent write}, `idempotency_key_required`, `failure_taxonomy` ∈ {interface error, semantic error, transport timeout, provider unavailable, budget exceeded}, `structured_diagnostic` (path, expected, found, allowed values), `output_evidence_kind` (brief §4 vocabulary), `validation_status_default` = computed-not-validated. *Result Feedback* record returned into the next reasoning step: `call_id`, `status`, `retry_count`, `diagnostic`, `unverified_flag`, `ledger_entry_ref`. Broker-level exactly-once for non-idempotent writes (ledger, leaderboard, registry) via keys, independent of the model's instructions.
- **Tradeoff.** Schema rigidity vs adapter flexibility; 200–500 tokens of envelope overhead per call (S19).
- **Unresolved uncertainty.** S16's zero task success means there is no evidence that schemas improve outcomes; S17 and S18 are abstract-only reads.

### F4. The Evidence Ledger must record claim type and verifier identity; "supported" is verifier-relative
- **Issue.** The ledger spec lists support/conflict, uncertainty, status and independence. S29 shows that identical agent outputs yield unsupported-citation rates from about 3% to about 18% depending on the verifier, with verifiers agreeing on what is supported (positive-specific agreement 0.90–0.96) but not on what to flag (0.27–0.30); a conformal guard calibrated on easy distractors caught only 37% of harder human-labelled negatives. S28 shows claim type matters: Kosmos statements grounded in data analysis were 85.5% accurate, literature-based 82.1%, but interpretive syntheses 57.9%, and the system "tends to make excessively strong claims" and to "conflate statistically significant results with scientifically valuable ones". S32 reports 38.78% average accuracy on multi-paper tool-augmented reasoning versus 83.5% for a human expert.
- **Source / location.** S29 arxiv.org/html/2607.20527v1; S28 arxiv.org/html/2511.02824v2 (evaluation and limitations sections); S32 abstract.
- **Importance.** High: CQA rationales in this case are literature-derived; a rationale built on an interpretive synthesis is the weakest class of claim and the one reviewers will test.
- **Recommended change (component 5, with 6 and 12).** *Claim* record: `claim_id`, `claim_text`, `claim_type` ∈ {data-derived, literature-extracted, interpretation/synthesis, expert statement}, `source_locator` (document id + span, or notebook/tool-run id + cell), `evidence_kind` (brief §4), `verifier_id`, `verifier_operating_point`, `verification_status` ∈ {supported, unsupported, contested, unverified}, `calibration_set_ref`, `independence_marker`, `uncertainty`. Policy: an interpretation/synthesis claim may not serve as sole support for a Criterion Registry entry without a Human Review Queue decision; verifier calibration uses a case-specific gold set, for which the authors' historical CQA rationale intake can be reused.
- **Tradeoff.** Human gold labelling (S29 suggests about 200 pairs for stable guarantees) and running more than one verifier cost time; the alternative is unquantified rationale quality.
- **Unresolved uncertainty.** Kosmos evaluated 102 statements across three reports with no code and no cost; S29 used 27–35B open models, so absolute rates for frontier verifiers are unknown.

### F5. Scoped Memory should be itemized, delta-updated, counter-tracked, small, and promotion-gated
- **Issue.** The spine's memory kinds and provisional/approved split are right, but the update mechanics and size limits are unspecified. S7 demonstrates "context collapse" when memory is rewritten wholesale (18,282 → 122 tokens; accuracy 66.7 → 57.1) and shows itemized delta updates with helpful/harmful counters outperforming GEPA on AppWorld (+17.0 vs +4.0 average) at 75.1% fewer rollouts; but without ground truth ACE lost 3.4 points on FiNER and the authors warn a weak Reflector can make context "noisy or even harmful". S8 shows failure-derived lessons help (46.5 → 49.7) but relies on self-judged success labels and gives no harmful-memory analysis. S9 shows skills help mainly as procedural anchors (65.7% of mechanisms) while retrieval precision collapses from 29.6% to 3.3% as pools grow from 5 to 100, and guidance is misapplied in 10.0% of skill-arm cases. S10 shows cross-role transfer losses of −4.8 to −7.5 points and training gains that do not transfer (+14.9 train / −2.7 test).
- **Source / location.** S7 arxiv.org/html/2510.04618v3 (Sections 3–5, Table 3–4); S8 arxiv.org/html/2509.25140v2; S9 arxiv.org/html/2608.14036v1; S10 arxiv.org/html/2606.23127v1.
- **Importance.** High: the brief's guardrail against candidate-specific lessons is necessary but not sufficient; unbounded or rewritten memory degrades the very runs it is meant to improve.
- **Recommended change (component 9).** *Memory Entry* record: `entry_id`, `kind` ∈ {evidence, tentative hypothesis, reusable procedure}, `scope` (task context / adapter / core; role), `status` ∈ {provisional, approved, retired}, `provenance` (run id, event sequence, ledger refs), `helpful_count`, `harmful_count`, `outcome_label_source` ∈ {self-judged, benchmark, human}, `promotion_eval_ref`. Policies: delta-only updates and deduplication (no whole-memory rewrite); active pool cap per scope with small retrieval top-k; procedures evolved in one adapter are not auto-promoted to core; promotion to `approved` requires a held-out evaluation on a fixed snapshot (component 13); self-judged counters are displayed as such.
- **Tradeoff.** True outcome labels are scarce in this case (historical CQAs and surufatinib only), so most counters will be self-judged; this must be visible rather than hidden.
- **Unresolved uncertainty.** None of S7–S10 are evidence-synthesis tasks; S10 explicitly excludes scientific research domains.

### F6. Continuation and budget: effort should scale with an actionable trigger, not with a default round count (bridging to 6b)
- **Issue.** The Run Controller lists stopping criteria but not how effort is set. S23 finds that "in 21 of 36 runs, higher reasoning effort does not improve accuracy", while on 6 of 9 benchmarks token usage still correlates with accuracy; S2 finds reasoning-heavy orchestrators underperform (GPT-5 high→low improved step success 0.251→0.302 with ~69% fewer tokens); S3 scales subagent count and tool calls to query complexity; S4 enforces hard budget termination. S7 shows online adaptation without reliable feedback can degrade.
- **Source / location.** S23 (findings section); S2 (Table 3 discussion); S3; S4 abstract.
- **Importance.** Medium: the brief already requires actionable-trigger continuation; the evidence supports it and warns against default extra effort.
- **Recommended change (component 10).** *Continuation Decision* record: `trigger_kind` ∈ {new external evidence, conflict in ledger, actionable gap, tool result with decision value, human edit}, `expected_gain_statement`, `budget_class`, `stop_reason` from the brief's list. Default policy: single screening round plus targeted continuation; budget class chosen from a declarative complexity table.
- **Tradeoff / uncertainty.** S23's finding concerns model reasoning effort, not review rounds; the debate and extra-round evidence is 6b's remit.
- **Revised after cross-review:** WS2's durable Open-Question Register (their C3) is the better home for the trigger; my Continuation Decision should be a round-level journal event citing `question_id`s rather than a standalone record.

### F7. The Event Journal must be attribution-ready: intent and effect separated, causal links, hash-verified projections
- **Issue.** The spine makes the journal the source of truth but does not say what an event must contain for later failure analysis. S19 separates agent intentions (validated JSON) from deterministic effects, keeps an append-only log, and verifies projections by SHA-256 hash, at 200–500 tokens per invocation, with zero output rejections in two case studies (n=2). S1 and S2 could only attribute failures because full traces with step-level roles existed; S20 builds causal graphs from logs for attribution; S23 and S26 show that log inspection is what reveals gaming, credential misuse and tool failures that accuracy metrics hide.
- **Source / location.** S19 arxiv.org/html/2602.23193v1; S20 abstract; S23; S26 abstract.
- **Importance.** Medium-high: the rebuttal must show how each criterion and ranking was reached; the Agentic Doping gap list already notes missing live activity events and no semantic diff.
- **Recommended change (component 11).** *Event* record: `seq`, `run_id`, `round_id`, `exchange_id`, `actor` (agent role / tool / human), `event_kind` ∈ {intent, dispatch, tool_result, verdict, human_decision, state_transition, checkpoint, projection_hash}, `artifact_refs` with versions, `parent_seq` (causal link), `budget_consumed`, `payload_hash`. Projections (progress, leaderboard view) are deterministic functions of the log and carry the hash of the event range they summarize. Make the schema sufficient to run a MAST-style annotation on the system's own traces as part of the evaluation harness.
- **Tradeoff.** Overhead and strict determinism of projections; S19 is a feasibility demonstration, not a benchmark result.
- **Unresolved uncertainty.** Whether hash-verified replay is needed for the local workbench or only for audited runs.

### F8. The Evaluation Harness should import the ABC / HAL / AstaBench requirements wholesale
- **Issue.** Component 13 names fixed snapshots, held-out material and matched budgets, but the literature shows how easily agent evaluations overstate: a do-nothing agent scored 38% on τ-bench; CVE-Bench overestimation fell 33% after applying ABC; an LLM judge accepted empty replies on WebArena (S22). HAL found scaffold choice can change cost 9× at similar accuracy and that log inspection revealed agents finding gold answers online (S23). AstaBench (S24) enforces date-cut standard tools so that a "winning" agent is not simply one with better information access, computes time-invariant cost from a frozen price map, reports 95% confidence intervals, and labels agents by openness and tooling; it also shows that end-to-end per-step success near 70% implies all-steps success near 0.7^10 ≈ 3%. τ²-bench's pass^k measures reliability over repeated runs and finds an 18–25% drop once a second actor controls part of the state (S25). S27 shows rank order is stable when using only mid-difficulty tasks (44–70% fewer tasks).
- **Source / location.** S22 arxiv.org/html/2507.02825v5; S23; S24 PDF pp. 5–10, 16–20; S25 arxiv.org/html/2506.07982v1; S27 abstract.
- **Importance.** High: the primary acceptance target (recover most historical CQAs; admit surufatinib with per-criterion reasons) is a benchmark with a disclosed answer, which is precisely the setting ABC warns about (T.5 isolate ground truth).
- **Recommended change (component 13).** *Evaluation Run* record: `policy_version`, `evidence_snapshot_id` with `date_cutoff`, `tool_set_id` (identical across compared policies), `budget_class`, `seeds` (k ≥ 3 for pass^k), `metrics` {historical-CQA recovery with the reference list held out from agents, surufatinib admission (binary, disclosed), per-criterion reason quality by rubric judge validated against a human pilot, tool failure rate, instruction violations, cost from frozen price map with CIs}, `baselines` {trivial agent that proposes no criteria, single-pass, fixed-round}, `log_inspection_checklist` (ground-truth access, tool failure, guessing, format ambiguity, candidate-specific leakage), `openness_and_tooling_class`. Report "unique all-pass under hard rules" and "top-ranked under score" as separate results, as the brief requires.
- **Tradeoff.** Repeated seeds multiply cost; the candidate universe is small, so confidence intervals will be wide and must be reported rather than suppressed.
- **Unresolved uncertainty.** No public benchmark matches criterion derivation from evidence; the harness must be built case-specifically, and judge validation needs a human pilot that does not yet exist.

### F9. Strategy evolution: adopt reflective prompt optimization offline with a held-out gate; do not optimize topology first
- **Issue.** The brief asks for evaluable strategy versions. S15 (ICLR 2026 Oral) mutates instructions only, using a scalar metric plus textual feedback, reaches +9.62% (Qwen3-8B) and +12.19% (GPT-4.1 mini) aggregate over baselines with 678–7,051 rollouts versus GRPO's 24,000, and transfers across models (+9.00%); its budget is dominated by validation and it "requires a well-defined evaluation metric". S7 beats GEPA on agent tasks by evolving memory rather than instructions. S6 (ICLR 2026) finds prompts should be optimized before topology. S1 cautions that tactical prompt fixes were "not consistent" when applied without structural verification.
- **Source / location.** S15 arxiv.org/html/2507.19457v2 (Sections 3–5); github.com/gepa-ai/gepa (MIT; DSPy and MCP adapters); S7; S6 abstract.
- **Importance.** Medium: it gives a concrete, evaluated mechanism for "evaluated strategy evolution" without touching weights, which the brief wants kept separate from model training.
- **Recommended change (component 13, Strategy Versioning).** Define a *Strategy Version* as {role prompts, delegation policy table, tool-selection policy, memory retrieval policy}. Candidate optimizer: GEPA-style reflective mutation driven by the harness metric and the textual feedback already produced by critiques and verification failures; run offline on a fixed snapshot; promote only on held-out criteria; keep rollback. Do not search over topology or spawn new agent roles automatically.
- **Tradeoff.** Needs a metric; the natural metric (recovery of historical CQAs) invites overfitting to the reference list, so criteria must be held out and the optimizer must never see the reference artifact.
- **Unresolved uncertainty.** No published evidence of GEPA or ACE in evidence-synthesis or scientific-screening tasks; evaluator exploitation is 6b's scope.

### F10. Agentic scientific discovery: keep a persistent epistemic state and preregistration; do not expect LLM diversity
- **Issue.** S30 (NeurIPS 2026 position track) argues current AI scientists lack belief revision and diversity, measuring inter-provider hypothesis similarity of 0.64–0.69 (near within-model 0.72–0.76) and an effective hypothesis count rising only from 2.9 to 3.6 when querying ten models; it proposes a persistent, mutable epistemic state and hypothesis preregistration. S31 finds only 38% of surveyed AI-scientist works provide reproducibility or novelty-verification artifacts. S28 lists stochastic non-convergence, sensitivity to objective phrasing, and no intermediate human interaction as Kosmos limitations. S24's end-to-end discovery scores are near zero for all-step completion.
- **Source / location.** S30 arxiv.org/html/2605.08956v2; S31 abstract; S28; S24 PDF p. 10.
- **Importance.** Medium-high: these are the structural reasons a single run of this MAS could "recover" criteria by consensus repetition rather than by evidence.
- **Recommended change (components 5, 6, 12, 13).** Treat the Criterion Registry plus Evidence Ledger as the persistent epistemic state: each criterion carries `belief_status` ∈ {proposed, supported, contested, refuted, retired}, `supporting_claim_refs`, `conflicting_claim_refs`, `revision_trigger`. Record the prespecified baseline and alternative configurations as a *Preregistration* event before any evaluation run (the brief already requires prespecification; make it an event with a hash). Require a "considered and rejected criteria" list in every proposal. Route interpretation-type support to the Human Review Queue. Do not rely on multiple LLM proposers for diversity; use human-sourced alternatives and the historical list only as a comparison reference.
- **Tradeoff.** More records and more human review; the alternative is a consensus artifact that looks like discovery.
- **Unresolved uncertainty.** S30 is a position paper; its empirical part concerns hypothesis generation, not criterion derivation.
