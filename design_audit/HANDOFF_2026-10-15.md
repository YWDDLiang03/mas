## 3. The recipe — minimal steps, no literature, everything inherited, reproducible

Run from the repository root. `TASK=task_01M4X892V1EAER2GHWE1RE19ZN`; all commands take
`--store var/primary/store --models var/primary/store/models_deepseek.toml`.

```bash
# 1. Let the three pending physicochemical rules enter scoring, by machine adjudication —
#    exactly how the Oct-14 board's MW / logP / HBD rules entered (its entries read
#    `confirmed_by: adj_…`). Without this step the freeze lands at rules@v5's 8 rules; with it,
#    ~11, which is the old baseline's composition rebuilt on the current criteria.
mas review adjudicate $TASK                       # NO — see below; adjudicating everything takes hours
mas review adjudicate $TASK --item <item_ref>     # repeat for the three rules, one call each
#    The three rule refs: rule_molecular-weight-against-the-class-typical-upp…@v1,
#    rule_lipophilicity-relative-to-the-upper-edge-of-th…@v1,
#    rule_topological-polar-surface-area-relative-to-the…@v1.
#    (List the queue with `mas review list`; items are the `human.review_requested` ones added
#    with round 10. If the machine adjudication for a rule is refused, that is itself a reading —
#    report it, do not force it.)

# 2. Freeze the scoring policy: measured criteria only, no eligibility gate on the rank.
mas rules confirm $TASK --allow-pending --coverage-floor 0 \
    --defer-capability predicted_property_lookup --defer-capability literature_retrieval \
    --defer-reason "...state the reason and the measured effect..."
#    WHY each flag, so no default decides policy again:
#      --coverage-floor 0        the ranking gate is the registered preference-coverage floor
#                                (0.5, a registered constant); the *mandated* floor must not be
#                                1.0 — the CLI default — because the reference compound's CSF1R
#                                cell is genuinely unobtainable (see §4), and the registration
#                                says eligibility is reported, not gated.
#      --defer predicted_property_lookup   the 12 predicted rules saturated coverage (every
#                                candidate incl. non-drugs cleared 0.5) and dominated the order.
#      --defer literature_retrieval        your instruction: no literature crawling; the rated
#                                crawl measured on 15 Oct was ~6 cells/min on 60 k cells.

# 3. The sweep — no literature, caches warm from 15 Oct, seed fixed:
mas run start $TASK --seed 0 --workers 4
#    Expect ~25 k cells (3,177 × ~8–11). Measured 15 Oct: the measured-only sweep ran at
#    hundreds of cells/min once warm; budget an hour and watch for external rate limits.

# 4. The board:
mas board show $TASK --all          # or: /api/leaderboard?task=$TASK on the workbench
#    Read it as in §4 — rank, coverage, eligibility, and the rankable-set size together.

# 5. CQA recovery (each command once; the intake is already recorded):
mas recovery report $TASK --mapping /home/yiwei3_duke/anny/cqa_mapping.json
#    Output lands in var/primary/recovery/$TASK/. The mapping is produced by an isolated
#    evaluator (never by a deriving role — the CLI refuses otherwise), and the file is
#    evaluator-only content: do not commit it to the repository.
```

**Reproducibility.** Every number above is reproducible from the store plus this file: the sweep
takes `--seed 0`; the freeze is a recorded rule set (`rules@vN`); the journal records each run's
binding (roster, config hash, commit, `max_documents`); and the commands are written down. Copying

`store.db` + `-wal` + `-shm`); the predictor interpreter and the API-key file path are the only
machine-specific settings (see `requirements.txt`).

## 4. How to read the result, and what "satisfactory" can and cannot promise

Read the board as **four numbers together** and never quote one alone: the reference compound's
rank, its `preference_coverage`, its eligibility fields (`clears_hard_rules`,
`clears_mandated_criteria`, `mandated_blocked_by`), and the **rankable-set size** (a rank among 16
and a rank among 3,177 mean different things). The registration's own rule: a `provisional`
candidate can hold a registered rank, and the report says in the same breath what is *not*
established for it.

**What is already measured and must be carried forward, not re-litigated:**

- The reference compound's **CSF1R curated potency is genuinely unobtainable**: ChEMBL and
  IUPHAR/BPS have no row, and the affinity predictor refuses it as out of applicability domain
  (Tanimoto 0.303 < 0.40; recorded before any prediction was inspected). 4 of its 5 mandated
  receptor cells are answered. The only source for that cell is the manuscript's Table 1 —
  i.e. the literature pass, which this handoff deliberately does not run.
- The 15 Oct `rules@v3` board is **not the registered reading**: its `mandated_coverage_floor`
  defaulted to 1.0, so only 16 candidates were positioned; raw score order over all 3,177 puts the
  reference compound #1,985 behind solvents. **Both readings stay in the record.** Do not "fix"
  the rank by choosing floors now that the numbers are known — that is the post hoc tuning the
  registration exists to prevent. The repair is the composition and the gate stated in §3, chosen
  from the registration and the Oct-14 precedent, not from the numbers.
- The honest expectation: under step 3's composition the rankable set should return to a drug-like
  size (the Oct-14 baseline: 95) and the reference compound should be **ranked** (coverage ≈
  7/11 ≥ 0.5). Whether it lands top-5 is a measurement, not a promise — the Oct-14 baseline, on a
  comparable instrument, had it **#4 of 95**. If it does not land top-5, report that; the
  machinery's first complete round is a result either way.

## 5. Every known problem, in one place

**Measurement/policy**
1. No *measurement profile* step: policy (composition, capabilities, floors) is set during runs,
   as it was on 15 Oct — the freeze CLI's default `--coverage-floor 1.0` became policy silently.
2. Coverage is a fragile gate: its meaning depends on the scoring composition; twelve predicted
   rules saturated it. Structural repair: stratify coverage by `determination_basis`.
3. The two consolidated, paper-shaped criteria (weakest-receptor potency; worst toxicity burden)
   are **pending/disputed** — registered but not scoring. Adding them is a policy choice that
   happens to favour balanced profiles (declared, never sneaked in).
4. 56 review items are queued; 25 proposer/critic disputes open; zero expert decisions recorded.
5. The literature pass has never run; the criteria it would evaluate (41 registered rules) are
   deferred, and the reference compound's missing CSF1R cell sits among them.

**Operational**
6. The store grows ~2 MB per candidate-sweep cell-block and reached 4.5 GB; the host hit 100 %
   disk (fixed by a 50 GB expansion on 15 Oct) and memory exhaustion (284 MB free, 5.3 GB swap).
   Preflight disk and memory before a sweep; expect ~2 GB of store growth per universe sweep.
7. `sqlite` reads time out while a sweep writes; wrap every query in `timeout` and prefer the
   read-only workbench (`http://127.0.0.1:8765`, JSON under `/api/`).
8. Killing a run means killing the **real python** (`fuser var/primary/store/store.lock`), not the
   shell wrapper; a wrapper's death leaves the run alive.
9. No watchdog on an outside servicer: a dead serving session left the pipeline idle 5.5 hours
   (04:39→10:16 on 15 Oct) before a human noticed.
10. The DeepSeek provider stalls intermittently mid-body; roster timeouts are now
    `deepseek_exact` 120 s / `deepseek_reasoning` 600 s (config, `var/primary/store/models_deepseek.toml`).

**Process/administration**
11. The old serving session is unrecoverable as-is (422 request-shape error, independent of the
    account hold); the account itself needs `claude.ai/restricted`.
12. `mas_audit.md` announces a sealed Section 6 that is absent from the file.
13. Merge/consolidate worked on 15 Oct (six consolidations, the first in the project) but the
    earlier schema-refusal failure mode was never root-caused; if the three physchem rules or the
    consolidated criteria fail to enter scoring, the refusal text is the place to look.
14. The criteria snapshot label reads `historical_baseline_pre_repair` for any export whose merge
