# Implementation Tasks (for the later implementation phase; nothing here is executed now)

Coordinating agent, 12 October 2026. Small implementable tasks derived from `optimized_design.md`, grouped into milestones M0–M8 in dependency order. Each task names its purpose, dependencies, inputs, outputs, acceptance criteria, and owner layer (core, adapter, case, UI, evaluation). Component ids (C1–C20), record names, states, and identifiers follow `optimized_design.md` Section 0. Tasks marked **[BLOCKED ON AUTHORS]** need inputs the package does not contain. "Acceptance" means a design-phase-stated check the implementation must pass; it never means a scientific result.

## Critical path

The critical path runs M0 (journal, registries) → M1 (ledger, criterion registry, identity) → M2 (protocol engine, run controller) → M3 (broker and first providers) → M4 (assessor, leaderboard) → M5.1 (queue, because confirmation gates `rules@v1`) → M7.1 and M8.3 (manifest and preregistration must exist before derivation) → M8.4–M8.9. Two external dependencies sit on this path and should be requested first: the authors' candidate-universe identity list and eleven-CQA list with attestation (T8.1, T8.2), and expert availability for confirmations and recovery judgments (T8.5, T8.8). The UI screens (M6) are off the critical path for producing records but on it for the human-review workflow; the queue screen (T6.9) should be built with M5.1. Evaluation arms beyond P0 (T7.2) and strategy promotion (T7.6) are off the critical path for the primary case and can follow once pilot variance exists.
