# Architecture Decisions

Coordinating agent, 12 October 2026. Each decision records context, the decision, alternatives considered, supporting evidence (workstream report and finding, literature source, or inspected repository path), tradeoffs, and status. Component ids (C1–C20) and vocabularies follow `optimized_design.md` Section 0. Workstream reports are under `agent_reports/`: WS1 `evidence_and_policy.md`, WS2 `mas_architecture.md`, WS3 `tools_and_data.md`, WS4 `human_review_and_ui.md`, WS5 `evaluation_and_improvement.md`, WS6a `current_agent_literature_a.md`, WS6b `current_agent_literature_b.md`, WS7 `reference_harness_inspection.md`. Literature source ids (S-numbers) refer to the tables in the two literature reports; "AD" is the Agentic Doping snapshot at commit `0007ad10`.

| ADR-31 | **Exposure to the historical list is recorded for people and templates, and recovery is reported in two views.** Every criterion-affecting `hd_`, every adapter template, and every global shaping artifact (objective text, dimension list, consolidation rule, derivation strategy) declares `historical_list_exposure`; a logged read of the list makes the reader `exposed` regardless of declaration; reads happen only through confirmed, logged commands, and the stored list is encrypted at rest under an evaluator-held key so that file access on a shared account is not a read (ADR-35, ADR-36); the review queue shows the list only for comparison adjudication after confirmation; global shaping artifacts must be verbatim public text or pass a criterion-content scan. | ADR-33 | **A run is complete when its candidate sweep is complete.** Within the run's bound `sweep_scope` (the full universe for a baseline run), every compound gets a row and every resolved compound an attempted cell for every rule in scope, breadth-first by rule in a registered order, randomized within a rule, with no short-circuit after a hard fail and a budget reserved per rule. `round_limit_reached` is the normal end of a single-pass run. | ADR-35 | **Two operator surfaces over one Operator API, as host infrastructure.** A terminal client (operating Linux hosts) and a browser workbench used in Chrome (operating Windows or Linux hosts) are clients of one Operator API; neither reads store files or keeps state. | ADR-37 | **Edit and continue through run chains.** Three terms are kept apart: resume (same run), round continuation (a round inside a run, including a person's `human_request` round, which is barred from evaluation-arm and prespecified runs), and run continuation (a new run in the same chain). Edits to what a run derived happen inside it through `hd_` records. Edits to bound fields, budget increases, and any continuation after a run ended start a run continuation whose kind follows from what changed (`refresh` for a new cutoff; otherwise `continue` with the parent's scope, or `rerun` for an approved Rerun Plan), reusing every record with an unchanged fingerprint. A parent that has not ended is closed, with its open review items withdrawn and raised again; closing a registered run early needs the evaluator and records a protocol deviation. Branches need confirmation; snapshots chain through `parent_snapshot_id`; a continuation that breaks comparability opens a new leaderboard; `chain_cost` is always reported; a continuation is outcome-informed, hence exploratory, once any snapshot or recovery comparison of its chain was published, unless it matches a stage-1 rule (a sensitivity configuration or the budget-extension rule). | Re-entering the same run after it ends, as Agentic Doping's continue mode does (same run id, one merged board; AD `orchestration/recommend.py` 209-218, 734): convenient, but it rewrites what that run's binding and completion claimed and mixes configurations inside one record.
