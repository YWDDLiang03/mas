# 导入自己的候选和观测数据

[English](../csv-input.md) · [安装与首次启动](installation.md)

从总览或 **New research** 进入 **Use own data**，选择 **Drug**、**Carrier** 或 **General**，先导入候选列表，再导入对应观测。界面支持上传 UTF-8 CSV 文件或粘贴 CSV 文本，并提供可下载模板。启动方式需要开启本地操作，见安装说明。

下方两个 CSV 示例均为**明确标注的合成格式示例**。候选名称、数值和条件只用于说明导入格式；实际研究请填写自己的候选和真实记录。[仓库模板](../../config/examples/) 只有表头，导入前至少需要填写一行数据。

## 候选列表

每个候选占一行，将 CSV 列映射到以下字段：

| 字段 | 是否必填 | 含义 |
| --- | --- | --- |
| `candidate_id` | 是 | 唯一文本编号，最多 200 个字符。 |
| `name` | 否 | 展示名称；为空时使用候选编号。 |
| `smiles` | 否 | 适用时填写声明的 SMILES。 |
| `inchikey` | 否 | 适用时填写声明的 InChIKey。 |
| `chembl_id` | 否 | 适用时填写声明的 ChEMBL 编号。 |
| `description` | 否 | 候选描述。 |

额外候选列会保留为元数据。测量观测填写在单独的观测表中。候选编号始终作为文本处理，`001` 与 `1` 是不同候选。使用电子表格准备数据时，应在输入或导出前将编号列设置为文本，以保留前导零。

合成格式示例 `candidates.csv`：

```csv
candidate_id,name,description
DEMO-A,Example carrier A,Synthetic format example
DEMO-B,Example carrier B,Synthetic format example
```

先保存候选列表，再导入观测。使用已有药物库时，观测中的编号必须与库中的实际标识一致，例如 InChIKey；导入器不会通过名称自动匹配外部化合物。可选结构标识按原样保留，CSV 导入不验证化学身份。

## 观测表

每条观测占一行。同一个候选可以有多个性质、重复观测或不同条件下的记录。

| 字段 | 是否必填 | 含义 |
| --- | --- | --- |
| `candidate_id` | 是 | 与本次选择的候选库完全一致的编号。 |
| `property` | 是 | 记录的性质或终点，例如 `particle_size`。 |
| `value` | 是 | 有限数值、`true` / `false`，或记录中的类别。 |
| `basis` | 是 | `measured`、`curated`、`predicted`、`simulated`、`derived` 中的一项，不自动推断。 |
| `unit` | 数值观测必填 | 记录中的单位；无量纲数值用 `1`。布尔值和类别可留空。 |
| `conditions` | 否 | 实验条件，支持普通文本或 JSON 对象。 |
| `source` | 否 | DOI、网址、实验笔记、数据集或其他来源引用。 |
| `summary` | 否 | 研究者对该观测的文字说明。 |

合成格式示例 `measurements.csv`，编号与上面的合成候选对应：

```csv
candidate_id,property,value,unit,basis,conditions,source,summary
DEMO-A,particle_size,120,nm,measured,DLS; aqueous dispersion; 25 C,Synthetic format example,Illustrative observation only
DEMO-B,particle_size,170,nm,measured,DLS; aqueous dispersion; 25 C,Synthetic format example,Illustrative observation only
```

实际数据应记录实验方法、人群、剂量、时长、介质、温度等相关条件。不同条件集在研究评估中保持独立。JSON 条件必须是有效对象；其中出现逗号或双引号时，需要按 CSV 规则引用和转义。不需要结构化字段时，用普通文本描述即可。

`conditions` 和 `source` 在导入结构上可选，已知时应填写，以便追溯观测的适用范围。缺少条件会产生提示，范围保留为未指定。`source` 为空时，保存的观测以文件名作为声明来源，同时在来源记录中保留“未填写明确来源”的状态。系统保留提交文本、其 UTF-8 内容哈希、文件名及 CSV 行号；哈希对应浏览器解码和可能的文本规范化之后提交的文本。

缺失观测应省略。必填值为空、NaN、非有限数值，以及 `NA`、`unknown`、`missing` 等缺失标记会被报告为输入错误。零和 `false` 是有效观测值。按实际情况声明证据类型，模型估计保留为预测或模拟记录。

## 预览、修正和保存

1. 选择或粘贴候选 CSV，检查列映射并验证。系统可识别部分常见别名，例如 `sample_id` 对应 `candidate_id`、`endpoint` 对应 `property`、`result` 对应 `value`；保存前仍应核对映射。
2. 修正提示的问题，再次验证。一列 CSV 最多映射到一个导入字段；预览有效后保存候选列表。
3. 选择该已保存候选库，导入观测 CSV，核对映射、单位、证据类型和实验条件后保存。
4. 在 **New research** 选择已保存数据，填写目标、必须具备的观测、硬条件和偏好，然后按配置的预算开始研究。

预览展示前十条数据，但会验证整个文件。行级错误标出 CSV 行号和字段；最多展示 200 条详细错误，同时保留总错误数。文件结构错误可能直接阻止预览打开。全部错误修正后才可保存；提示信息说明已接受数据中需要注意的范围。

| 报告的问题 | 处理方式 |
| --- | --- |
| 必填字段没有映射到列 | 映射到对应列，或补充该列后重新选择文件。 |
| 候选编号重复 | 每个编号只保留一条候选记录；重复观测写入观测表。 |
| 观测编号不在所选库中 | 选择正确候选库，或在原始 CSV 中修正编号。 |
| 数值缺少单位 | 填写记录中的单位；无量纲数值填写 `1`。 |
| 证据类型无效、值缺失或数值非有限 | 填写实际且受支持的类型和值；缺失观测省略。 |
| 条件 JSON 无效 | 修正为有效 JSON 对象，或改用普通文本。 |
| CSV 损坏、各行列数不一致或编码异常 | 重新导出 UTF-8 CSV；对含逗号、双引号或换行的字段正确引用。 |

列名必须唯一且非空；接受 UTF-8 字节顺序标记。当前每个文件最多 **8 MB UTF-8 文本、50,000 条数据行、64 列**。只有表头或内容为空的文件会被拒绝；超过限制时先拆分文件。

每个保存的数据集都有不可变身份。同一文件和映射的重复导入返回已有版本；内容或映射改变时创建新版本。通过界面重新导入修正内容，可保留原始提交的可追溯性。

## 在研究中使用观测

上传数据适配器按所提供记录中的性质、单位和条件评估药物、载体及一般候选。可选的已保存证据集合可辅助标准构思；专用药物适配器也支持已记录药物库和外部证据工具。

明确写出硬条件，说明对应性质、单位和适用范围。条件无法与提供的数据绑定时，工作流会补问必要信息。未指定偏好方向的必需观测按数据可用性记录。预测与直接观测保持区别；没有有效硬条件的研究会报告资格判断尚未就绪。

导入检查文件结构、编号和声明的观测元数据。科学审查、标准构思和资格判断在研究工作流中完成。上面的合成例子仅展示格式，未经过科学评估。
